# 星云智能体 · 使用指南

> 项目根（真实路径）：`E:\星云\星云智能体\strata-agent`
> 工作区别名「星云智能体」。本文所有相对路径均基于此根。

---

## 0. 一句话总览

星云智能体是 Strata 的增强发行版：**前端只有一份权威源**，通过两种入口（寄生 / 独立）共用。

- **速度由上游模型决定，不由模式决定**——两种模式默认都连同一个推理后端时，逐 token 速度相同。
- **只开发、只维护一份前端**（`serve/web/`）。寄生入口读它的同步副本，独立入口直接读它。

```
                 ┌────────────────────────────────┐
   唯一权威源 →  │ strata-agent\serve\web\ （一份）│
                 └──────────────┬─────────────────┘
              deploy_to_strata.bat │ robocopy/镜像（方向永不逆转）
                            ▼
              Strata-main\serve\web\  ← 寄生入口读这份副本
```

- 前端逻辑只有一份：`app.js / admin.js / i18n.js / app.css / index.html …`，两个入口共用，不存在「两个版本」。
- 开发只改工作区 `serve\web\`（权威源）。

## 1. 两种模式怎么选

| 维度 | 寄生模式（推荐日常） | 独立模式 |
|---|---|---|
| 谁服务前端 | Strata-main 后端 | 星云 `runtime/gateway.py` 自带 HTTP |
| 前端代码 | 部署到 Strata 的 `serve\web\`（从权威源同步） | 直接用工作区 `serve\web\` |
| 工具执行 | Strata 原生 MCP（含审批/知识库/工作空间注入，功能最全） | 默认透明代理交上游；纯 OpenAI 上游开 `AGENT_MODE=1` 由网关本地执行 |
| 支持上游 | 仅 Strata | 任意 OpenAI 兼容端点（OpenAI / Ollama / LM Studio / Strata） |
| 审批弹窗 / 知识库 | 全功能 | 需上游配合；`--agent` 连纯 OpenAI 时暂不支持审批弹窗 |
| 看图（多模态） | 依赖宿主补丁 `apply_host_patch.py`，**升级后需重放** | 网关三层已打通，无需补丁 |
| 启动后改动如何生效 | 前端：`deploy_to_strata.bat` 同步 + 重启 Strata；后端/配置：重启 Strata | 刷新浏览器即生效（后端改动重启网关） |
| 额外维护负担 | 每次 Strata 升级要重放前端部署 + 看图补丁 | 无（刷新即可） |

**建议**：日常图省事 → 寄生；要接云端/其它本地模型、或不想被 Strata 升级冲掉补丁 → 独立。两者前端同源、速度相同。

> **性能对比先确认前提**：两种模式连的是否同一上游模型。同模型则速度相同——模式只影响「前端服务归属 + 工具执行归属」，不影响推理本身。真正决定快慢的是换模型 / 换量化档位。

## 2. 三个 BAT（根目录）

| 文件 | 作用 | 何时用 |
|---|---|---|
| `01deploy_to_strata.bat` | 把工作区 `serve\web\` 镜像同步到 `E:\Program Files\Strata-main\serve\web`（可带参数指定其它目标） | Strata 升级后；前端改动后 |
| `02deploy_host_patch.bat` | 重放宿主多模态补丁（含 `START-HERE.bat` 的补丁段） | Strata 升级后（会重写 serve/ 冲掉补丁） |
| `run_standalone.bat` | 启动独立模式（自带前端 + API 代理） | 接任意上游 / 不依赖 Strata-main |

- BAT 保持 **GBK 编码**保存，勿用 UTF-8 编辑器另存覆盖，否则中文路径乱码（提示已尽量纯 ASCII）。
- 含中文路径「星云智能体」的命令行直调 robocopy 会因代码页失败，**优先双击 BAT**；脚本自动化需先 `chcp 65001`。
- 部署脚本 `tools/deploy_frontend.py` 解析出的源就是 `strata-agent\serve\web`，按 **MD5 幂等**：无差异则不动文件。

### 部署铁律

- 星云工作区 `serve/web/` 是唯一真相源；任何 Strata 实例的 `serve/web/` 都是它的镜像，**方向永不逆转**。
- 部署脚本**只复制前端文件、不装后端**：目标 `Strata-main` 后端进程必须已在原位并能正常启动，BAT 只把前端镜像过去。目标目录不存在会直接 `[FAIL]`。
- 单点风险防护：建议定期把 `serve/web/` 打包 zip 存到云盘或 Git（工作区丢失则 BAT 无法恢复）。

## 3. 独立模式启动

双击 `run_standalone.bat`，浏览器打开 `http://127.0.0.1:8099`。

bat 头部参数：
```batch
set UPSTREAM_URL=http://127.0.0.1:8080/v1    ← 上游地址（Strata 或任意兼容端点）
set MODEL=strata                              ← 默认模型名
set API_KEY=                                  ← API Key（可选）
set PORT=8099                                 ← 前端访问端口
set AGENT_MODE=0                              ← 0=透明代理(连 Strata)；1=网关自带 agent loop(连纯 OpenAI 等无 MCP 上游)
```

- 连 Strata：保持 `AGENT_MODE=0`（用 Strata 原生 MCP，含审批/知识库/工作空间注入）。
- 连纯 OpenAI / 无原生 MCP 的上游：改 `AGENT_MODE=1`，由网关本地 MCP 服务器执行工具，聊天页 MCP 卡片会显示本地 9 个服务器，流式响应实时注入 `strata_mcp` 事件。

## 4. 多模态「让模型真看图」

要模型真能看图，需三层打通（向后兼容，`call_tool` 返回 `str` 时行为不变）：
`_mcp_base` 加结构化 image 返回通道 + browser screenshot 返回 base64 image 块 + `executor.py` 组装多模态消息。

**寄生模式看图依赖宿主补丁**：MCP 服务端已产出 image 块，第三方客户端会把 result 拍平成 text，须由 `apply_host_patch.py` 在 `serve/mcp.py` 的 `call()` 末尾与 `serve/server.py` 的 results 组装两处透传为结构化 image part，才能送达模型。

- 补丁权威源：`tools/apply_host_patch.py`，**锚点式重放**（按行 strip 匹配、幂等 MARK 标记、改写前自动备份、锚点命中数≠1 报错交人工）。
- **每次 Strata 升级都会重写 `serve/` 冲掉补丁**——升级后必须双击 `deploy_host_patch.bat` 重放，否则寄生看图失效（普通聊天不受影响）。
- `START-HERE.bat` 本身也被补丁管理；首次升级需手动跑一次 `deploy_host_patch.bat` 之后才永久自动。
- ⚠️ **当前状态**：`START-HERE.bat` 暂不在根目录，说明补丁尚未重放到位——首次使用前先双击一次 `deploy_host_patch.bat`。

### 看图复验夹具（CI 门禁）

- `tools/_live_vision.py` + `vision_test.html`（多物体：红圆 / 蓝矩形 / 绿三角 / 橙菱形 / 黄色 PARROT / 紫底）；配套截图 `vision_test_shot.png`。
- `_live_vision.py --assert` 为 CI 回归门禁：硬断言 `PARROT + purple` 必须**双路通过**才绿灯；软断言（红/绿/蓝/橙）为多物体能力探针，仅警告。
- 量化小模型（IQ3_S 级）对多物体 / 小图形分辨力有限，常只识别主背景 + 主文字——多物体断言作软警告，CI 门禁只锁主特征。
- 复验时 `max_tokens` 设 800；CI 断言需识别**否定语境**（「NO red circles」不能因含子串「no red」误判为 PASS）。

## 6. MCP 与技能管理（Tools 标签页）

顶部 **Tools** 页可在网页上增删改 MCP server 与技能，无需手改配置文件。

- 管理接口由**网关**提供（Strata 后端不可改）。独立模式：网关已在跑，Tools 页直接可用；寄生模式：需先跑 `run_standalone.bat` 启动网关，否则页面会提示并给启动命令。页面自动探测（先同源，再 `127.0.0.1:8099`）。

| 对象 | 操作 |
|---|---|
| MCP server | 新增 / 编辑 / 删除 / 试连 |
| 技能 | 新增 / 编辑 / 删除 |
| 批量 | 粘贴 Claude Desktop `mcpServers` JSON 一次性导入 |

**试连**真正启动进程、列工具再关掉，不落盘——验证命令/参数，不污染配置。

### 技能双写机制（重要）

| 位置 | 给谁用 | 内容 |
|---|---|---|
| `skills/<名称>.yaml` | 网关 | 保留 `$SKILL_DIR` 占位符，可移植，带 permissions/triggers |
| `config/mcp_servers.json` 展开条目 | Strata | `$SKILL_DIR` 展开为绝对路径，带 `_skill` 标记 |

`$SKILL_DIR` 指 `skills/` 目录本身。展开条目带 `_skill`，删技能时一并清理；直接删这类条目会被拒绝并提示去删技能。当前技能目录仅 `example.yaml` 示例。

### 改动如何生效

保存后网关**自动热重载**。寄生模式 Strata 只在启动时读配置——**需重启 Strata** 才更新工具列表（每次保存页面都会提示）。

### 安全设计

- 只监听 `127.0.0.1`。
- 每次写入前自动备份到 `config/.backups/`（滚动保留最近 20 份）。
- 名称只允许字母 / 数字 / `.` / `_` / `-`，杜绝路径穿越。
- 客户端提交字段只取 `command/args/cwd/env`，无法伪造 `_skill` 等内部标记。
- 每次增删改写审计日志 `data/audit.jsonl`。

回滚：把 `config/.backups/mcp_servers.<时间戳>.json` 复制回 `config/mcp_servers.json`。

## 7. 中文编码（工具写入/读取失败的根因，已修复）

**根因**：MCP stdio 通道编码错配。规范是 UTF-8，但双击 bat 不设置 `PYTHONUTF8`，Python 的 `stdin/stdout` 跟随系统区域编码（中文 Windows = GBK），收发两个方向同时坏：

| 方向 | 机制 | 现象 |
|---|---|---|
| 出：工具结果 → 前端 | 服务端按 GBK 写，客户端按 UTF-8 读 | 中文变 ` ` |
| 入：参数 → 服务端 | 客户端发 UTF-8，服务端按 GBK 解 | 孤立代理字符 → `UnicodeEncodeError` → write 失败、0 字节文件 |

**修法（把编码钉死 UTF-8）**：

| 位置 | 改动 |
|---|---|
| `servers/_mcp_base.py` | stdio 重设 UTF-8，收发走 `sys.stdin/stdout.buffer` 显式 UTF-8，绕过文本层 |
| `servers/shell_server.py` | 子命令输出按字节捕获 + 智能解码；子进程 `PYTHONUTF8=1` |
| `servers/fs_server.py` | 读文件按字节 + 智能解码（顺带正确读旧 GBK 文件） |
| `servers/browser_server.py` | Edge 输出按字节捕获再解码 |
| `runtime/executor.py` | 网关 MCP 客户端 `text=True` 补 `encoding=utf-8, errors=replace` |
| `runtime/textenc.py` | 新增共用 `smart_decode` |

**「先 UTF-8 再回落 GBK」**：GBK 双字节几乎不可能是合法 UTF-8，回落判定无歧义；反向（UTF-8 当 GBK）永远"成功"却全乱码——这正是 bug 长期隐藏的原因。

**读写对称铁律**：凡按代码页（GBK）写出的文件，读取侧也要镜像（读字节 → 试 UTF-8 → 回退 GBK），否则幂等/二次读取会 `UnicodeDecodeError` 崩溃。

> MCP 配置写的是**绝对路径**，改本地即刻生效、不需部署；但必须**重启对应 MCP server** 才加载新代码。`servers/` 下脚本改动需重启该 server，重启会切断经它执行工具的当前会话（自重启），由用户决定时机。

## 8. 多语言（中 / 英）

- **顶栏按钮**：右上角 `中 / EN` 一键切换。
- **关于页下拉**：底部显式选 `中文` / `English`。

## 12. 上下文压缩（自动）

- 自动压缩阈值为前端硬编码常量 `AUTO_COMPACT_PCT=85`，settings 无对应字段；若要做可调阈值，需在 `app.js` 默认/保存/读取**三处对称**新增字段（遵守读写对称铁律）。
- 自适应触发点 = 窗口 − 安全余量；余量 ≥ 压缩请求自身输入 + 一次往返（压缩动作本身也烧 token，近 100% 才触发会塞不下压缩请求）。
- 压缩策略是 **append-only 分区冻结**（为前缀缓存热），自适应应"晚压 + 一次压够"，禁止频繁小压缩打断缓存。
- 当前只有占用比例 + 压缩成本两个信号，质量退化无可量化反馈（小模型尤甚），故纯自适应 = 伪自适应，实际只做「按窗口调余量」。
